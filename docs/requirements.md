# waltz 要件定義 v0.1

> waltz（ワルツ）。オウンドメディア（記事）と会員コミュニティを、1つのアプリでセルフホストできるオープンソース基盤。

## 1. 目的と位置づけ

| 項目 | 内容 |
|---|---|
| 解決したいこと | 企業がオウンドメディアを始めると、記事は WordPress、会員の場は別の SaaS、計測はまた別、と分かれ、読者が「読む人」から「参加する人」へ移る導線が切れる |
| 提供価値 | 記事を読んだ人が、そのまま同じサイトの中で質問し、つながり、イベントに来る。この一連を1つのアプリ・1つのデータベースで持てる |
| CMS の範囲 | WordPress の代替は狙わない。記事・固定ページ・カテゴリ・タグ・SEO/AIO 設定に絞った簡易 CMS |
| コミュニティの範囲 | 旧世代の SNS エンジン（OpenPNE 等の掲示板型）ではなく、カード型タイムライン・テーマ別コミュニティ・肩書き付きプロフィールを中心にした、今の仕事系 SNS（例: YOUTRUST）に近い体験 |
| 想定利用者 | 中小企業・スタートアップのマーケ担当／広報／コミュニティマネージャー、それを請け負う制作会社 |

## 2. 利用者と権限

| ロール | できること |
|---|---|
| 訪問者（未ログイン） | 記事を読む、公開コミュニティの投稿を読む、会員登録 |
| メンバー | 投稿・コメント・いいね・フォロー、コミュニティ参加、プロフィール編集、通知を見る |
| 編集者 | メンバーの権限＋記事・固定ページ・カテゴリの作成と編集、画像アップロード |
| 管理者 | 編集者の権限＋サイト設定、コミュニティ作成、メンバーのロール変更、投稿の非表示（モデレーション） |

- 管理者になれるのは、環境変数 `ADMIN_EMAIL` と同じメールアドレスで登録した人だけ。開発環境に限り、未設定なら最初の登録者を管理者にする（本番公開の直後に、第三者が先に登録して乗っ取るのを防ぐため）

## 3. 機能要件

### 3-1. メディア（簡易CMS）

| ID | 要件 | MVP |
|---|---|---|
| M-01 | 記事の作成・編集・下書き保存・公開・非公開。本文は Markdown、編集画面でプレビュー | ✅ |
| M-02 | 記事の項目: タイトル、スラッグ（URL）、抜粋、本文、アイキャッチ画像、カテゴリ（1つ）、タグ（複数）、注目記事フラグ、SEOタイトル、メタディスクリプション、公開日時 | ✅ |
| M-03 | 固定ページ（会社概要・プライバシーポリシー等）を `/p/{slug}` で公開 | ✅ |
| M-04 | 画像アップロード（jpg/png/webp/gif、5MBまで）。保存先はローカルディスク、URL を本文へ挿入 | ✅ |
| M-05 | Markdown ファイル（.md）の取り込み。外部の記事作成ツールで書いた原稿を、そのまま下書きにできる | ✅ |
| M-06 | 公開側: トップ（注目記事・新着・カテゴリ）、記事一覧（検索・ページ送り）、カテゴリ別、タグ別、記事詳細（目次・関連記事・共有） | ✅ |
| M-07 | 記事詳細の下に「この記事について話す」。記事をコミュニティへ共有した投稿と、その会話を表示 | ✅ |
| M-08 | 予約公開（公開日時が未来なら公開側に出さない） | ✅ |
| M-09 | リビジョン履歴、複数人の同時編集、ブロックエディタ | 対象外（WordPress の領域） |

### 3-2. 検索エンジン・生成AI への最適化（SEO/AIO）

| ID | 要件 | MVP |
|---|---|---|
| S-01 | `sitemap.xml`、`robots.txt`、RSS（`/feed.xml`）を自動生成 | ✅ |
| S-02 | `llms.txt` を自動生成（サイト概要と公開記事の一覧。生成AIがサイトを読み取る入口） | ✅ |
| S-03 | 記事ごとに構造化データ（JSON-LD の Article／BreadcrumbList）、OGP、canonical を出力 | ✅ |
| S-04 | 公開側はサーバー側で HTML を返す（JavaScript を実行しないクローラーにも本文が見える） | ✅ |

### 3-3. コミュニティ

| ID | 要件 | MVP |
|---|---|---|
| C-01 | ホームのタイムライン。「おすすめ（すべて）」「フォロー中（フォローした人と参加コミュニティ）」の2タブ。カードに名前・肩書き・投稿時刻・本文・いいね数・コメント数 | ✅ |
| C-02 | 投稿作成。投稿先は「タイムライン全体」か「参加中のコミュニティ」。種別は「投稿」「質問」 | ✅ |
| C-03 | テーマ別コミュニティ。一覧と発見（参加人数順）、参加・退出、コミュニティ内のトピック（投稿）・イベント・メンバーの3タブ | ✅ |
| C-04 | コミュニティイベント。タイトル、日時、場所（オンライン可）、説明、申込URL（外部フォームやイベントツールへ） | ✅ |
| C-05 | プロフィール。表示名、ハンドル（@名前）、肩書き（職種・会社）、自己紹介、リンク、投稿一覧、フォロー／フォロワー数 | ✅ |
| C-06 | フォロー、いいね、コメント | ✅ |
| C-07 | 通知（いいね・コメント・フォロー・コミュニティ参加）。未読数をナビに表示 | ✅ |
| C-08 | 記事の共有。記事ページから一言を添えてコミュニティへ投稿すると、記事カードとして表示 | ✅ |
| C-09 | 発見タブ。人気のコミュニティ、新しいメンバー、注目の記事 | ✅ |
| C-10 | モデレーション。管理者が投稿を非表示にできる。投稿者本人は削除できる | ✅ |
| C-11 | ダイレクトメッセージ、通報、画像付き投稿、メンション、非公開コミュニティ | 次期 |

### 3-4. 管理画面

| ID | 要件 | MVP |
|---|---|---|
| A-01 | ダッシュボード: 公開記事数、メンバー数、今週の投稿数、新着コメント、直近の登録者 | ✅ |
| A-02 | 記事・固定ページ・カテゴリ管理 | ✅ |
| A-03 | コミュニティ管理（作成・編集・アーカイブ） | ✅ |
| A-04 | メンバー管理（ロール変更） | ✅ |
| A-05 | モデレーション（非表示にした投稿の一覧と復帰） | ✅ |
| A-06 | サイト設定: サイト名、キャッチコピー、説明文、テーマカラー、計測ID（GA4 測定ID・外部計測タグの読み込みURL）、パートナー導線の表示・非表示 | ✅ |

### 3-5. 拡張・連携

| ID | 要件 | MVP |
|---|---|---|
| X-01 | 計測タグの差し込み口（GA4 測定ID、外部タグの script URL）。任意の HTML を貼る方式にはしない（管理画面の乗っ取り時に被害が広がるため） | ✅ |
| X-02 | パートナー導線（記事作成支援・カスタマイズ開発・取材撮影の相談先）。設定で非表示にできる | ✅ |
| X-03 | 記事の取り込み・書き出し API（外部の記事作成ツールから下書きを直接送る） | 次期 |
| X-04 | Webhook（会員登録・イベント申込を CRM/MA へ渡す） | 次期 |

## 4. 非機能要件

| 区分 | 要件 |
|---|---|
| 導入 | `npm install` → `npm run setup` → `npm run dev` の3手順で、サンプルデータ入りのサイトが起動する。データベースはファイル1つ（SQLite）。外部サービスの契約は不要 |
| 運用 | Docker イメージで本番起動できる。データは `data/` ディレクトリ1か所（DBファイルとアップロード画像）にまとまり、バックアップはそのコピーで済む |
| 性能 | 記事詳細のサーバー応答 300ms 以内（記事1万件・会員1万人規模まで） |
| セキュリティ | 管理画面は各ページとサーバー処理の両方で権限を確認する（レイアウトだけの確認は迂回できる）。ログイン後の戻り先は同じサイト内のパスに限る。予約公開前の記事はコミュニティに共有できない。パスワードは scrypt でハッシュ化。セッショントークンは DB にハッシュ値だけを保存し、Cookie は httpOnly・SameSite=Lax（本番は Secure）。Markdown の出力は許可リスト方式で無害化。権限の確認は画面ではなくサーバー側の各処理で行う。アップロードは拡張子と中身の両方で画像か確認する |
| 表示 | スマートフォン優先。コミュニティはスマホで下部タブ、PCで3カラム。日本語の改行規則（行頭禁則）を守る |
| アクセシビリティ | タップ領域 44px 以上、文字コントラスト 4.5:1 以上、画像の代替テキスト入力欄 |
| ライセンス | MIT |

## 5. 技術構成

| 層 | 採用 | 理由 |
|---|---|---|
| フレームワーク | Next.js（App Router）＋ TypeScript | 公開側をサーバーで描画でき、SEO/AIO に強い。利用者・開発者が最も多い |
| DB | SQLite（better-sqlite3）＋ Drizzle ORM | 追加契約なしで動く。Drizzle で型安全に書き、将来 PostgreSQL へ移せる |
| スタイル | Tailwind CSS | 制作会社が改造しやすい |
| Markdown | marked ＋ sanitize-html | 軽量。出力は許可リストで無害化 |
| 認証 | 自前（メール＋パスワード、DBセッション） | 外部の認証サービスに依存しない。次期に OAuth を追加 |

## 7. 受け入れ条件（MVP）

1. 初回セットアップ後、サンプルの記事・コミュニティ・投稿が入ったサイトがブラウザで見られる
2. 新規登録 → コミュニティ参加 → 投稿 → 別ユーザーがいいね・コメント → 通知が届く、まで一通り動く
3. 管理画面で記事を書いて公開すると、トップ・一覧・sitemap・RSS・llms.txt に反映される
4. 記事をコミュニティへ共有すると、記事詳細の「この記事について話す」に出る
5. メンバー権限のユーザーが管理画面の処理を直接呼んでも拒否される
6. スマホ幅（375px）で横スクロールが出ない
